# COPE 当前目标、实现与发展路线

更新日期：2026-09-14。本文是当前状态入口；历史计划见 [AGENTS.md](../AGENTS.md)，逐次实验的固定配置与证据见 [goal/README.md](../goal/README.md)。本文不改变已经执行的配方和原始指标。

## 当前目标与边界

**先找到一种能把大模型的题目相关信息传给小模型、并带来可验证增益的方法。** 两端模型完全冻结，只训练中间接口，不使用学生 LoRA 或教师微调。教师在一次部署请求中只处理问题及可用上下文，不接收参考答案；学生的监督答案只用于训练损失。学生前向保留到接口的梯度。

目标经历了三次收敛：最初设计共享有序前缀，随后明确双冻结和学生直接 Decode，再将“有效信息传递”确立为当前优先目标。**学生不对问题做 embedding/Prefill 是候选路线，非所有实验的硬约束。** 后续生成 token 仍正常 embedding。双方看到完整问题的组评估附加指导；学生不见问题的组评估上下文替代，两者分别解释。

原始 COPE 长期命题仍保留：一个教师、共享 projector、有序 latent 前缀，服务不同规模学生和通信预算。MRL 多宽度与跨学生共享应在有效信号确认后展开；当前没有证据证明这套联合命题成立。

## 已完成的版本与发现

| 版本 | 实际方法 | 已完成工作 | 研究判断 |
|---|---|---|---|
| [v1](../goal/v1/results.md) | 教师冻结、学生 LoRA，单学生满宽 latent | 4 组各 128 步，128 题留出，54.68 分钟 | 历史偏离方案；正确 68.75%，无 latent 64.06%，但未优于常量/错配，不能支持当前双冻结目标 |
| [v2](../goal/v2/results.md) | 两端冻结；连续前缀 + 学生完整问题 Prefill；多宽度对照 | 4 组各 128 步，19 项各 128 题评测，148.81 分钟 | 短宽度相对满宽后截断有局部收益，满宽退化；未证明输入相关收益，也不是学生直接 Decode |
| [v3](../goal/v3/results.md) | 两端冻结；3 种接入 × 2 个教师层位，固定 512 宽度 | 6 候选 + 入选结构 2 控制训练；20 项评测；累计 176.28 分钟 | 完成但未通过确认。正确组 55.86%，训练错配 59.38%，推理错配 56.25%，尚未找到可确认的有效信息通道 |

以上不同版本的数据、评分和训练边界不同，不能用跨版本分数比较改进。v1/v2 使用同一批样本；v3 排除其全部 1,152 个样本，重新划分 512 train / 32 calibration / 64 dev / 256 holdout，官方 GSM8K test 未使用。

V3 的原始学生有 197/256 题未解析，正确接口组只有 3/256 题未解析。因此相对原始学生的得分提升同时受输出格式影响，不能解释为同等幅度的数学能力提升。正确 latent 未胜过错配控制是更直接的限制。两种替代问题 KV 候选在开发集只有 0–1/64 题正确；这说明本次压缩容量、训练预算和合成 KV 配方未奏效，不能外推为所有 KV 传递或 hidden 接口不可行。

## 三种 V3 路径具体是什么

教师 Qwen3-14B 在 GPU 0，学生 Qwen3-1.7B 在 GPU 1，均 BF16、eval、冻结。教师末层 `[1,n,5120]` 或第 20 块后状态，池化为 32 slot，经 projector 得到 `[1,32,512]` FP32 latent，在学生侧读取。每个候选单独训练接口，没有跨候选联合共享训练。

- **embedding**：reader 输出 `[1,32,2048]` 连续前缀，拼接完整问题的 embedding，学生执行 Prefill 后生成。
- **kv_add**：reader 为学生 28 层各生成 K、V，每个形状 `[1,8,32,128]`；学生对完整问题执行 Prefill，可读取这些额外记忆位置。
- **kv_replace**：相同形状的合成 KV 代替问题历史。学生仅接收固定启动 token 271，再自回归生成，不读取原始问题 token。

这里 KV 是通过生成损失学习的合成记忆，不是由教师末层 hidden 精确还原学生原生问题 KV，也没有读取或映射教师原生 KV。输出 hidden size 相同只保证张量宽度相容，不保证语义、层间状态和位置兼容。

## 运行与复核入口

```bash
uv sync --extra experiment --extra dev
python -m cope.search_experiment validate --config goal/v3/config.json
bash scripts/launch_v3.sh --print-command
python -m pytest -q
```

上述 validate 只核验配方，print-command 只显示命令，不启动训练。实际 launch 是服务器专用入口，读取固定资产绝对路径；复用前须检查硬件、剩余磁盘、pueue 组和 GPU 全局锁。不能把旧 run ID 当成新实验目录，也不能直接覆盖已用的 prepared data。

服务器工作根为 `/root/autodl-tmp/COPE`，原始数据和权重在 `/root/autodl-tmp`。完整日志、逐题预测、接口/优化器/RNG 检查点和源码归档仍留服务器，Git 保存可审计的小型记录。各 run 的 `manifest.json`、`artifacts.json` 和 supplemental audit 给出路径和哈希。

## 已知实现和证据限制

1. v2 在跨卡复制完整 latent 后才截前缀，实际各宽度均复制 64 KiB/题。较短逻辑 payload 不是实测传输下降；原始结果及补充通信审计已分开保留。
2. v3 原生 cache 工程检查采用独立 FP32 学生副本，正式模型仍 BF16；显存峰值含验证副本，不能作为单个训练组的峰值。
3. v3 检查点保存优化器与随机状态，并实际加载最终接口用于评测；自动恢复仅覆盖训练前失败和预算继承，**尚无完整的中途训练断点续跑流程**。
4. v3 各结构参数量、Prefill 工作量不同，等步数和样本曝光不代表等 FLOPs。在线延迟包含实际输出长度差异，不构成等质量加速结论。
5. 当前只测一个模型组合、一个数学数据来源、单种子。开发筛选只有 64 题，入选结构相对推理错配仅多答对 1 题；独立确认没有通过。
6. 当前数值解析仍存在严重的输出格式混杂。所有主结果沿用启动前固定评分，不能事后挑解析器提高某组分数。

## 后续发展：先定位失败原因，再扩展 COPE

以下是待注册方案，**没有自动建立或启动 v4**，也不承诺某一路径必然可行。

| 顺序 | 要回答的问题 | 候选工作 | 进入下一步的证据 |
|---|---|---|---|
| 1. 评测诊断 | 收益有多少来自格式适应？ | 对既有失败输出做有标签的事后误差分类；在新版本独立校准集上固定健壮评分/提示，再锁定新评测；保留常量和错配控制 | 格式成功率与任务正确率可区分，不能依靠修改当前留出评分获得“正结果” |
| 2. 信号与接入诊断 | 教师信息是否可读、压缩是否丢失信息？ | 先选少量独立对照：教师文本提示（额外 Decode 成本单列）、更多 slot/逐 token hidden 的高容量接口、可学习汇聚或外部 cross-attention；每次改变一类主要因素 | 正确信息相对无信息、常量、训练错配及推理错配产生可靠净增益 |
| 3. 直接 Decode 专项 | 能否替代学生问题历史？ | 原生学生 KV 交接作为工程正对照；训练时用原生学生状态作辅助对齐目标，或探索教师 KV 映射；部署仍只允许题目可用信息 | 独立样本可生成题目相关答案，明显优于固定/错配记忆；仅 NLL 下降不够 |
| 4. 有序前缀 | 同一接口的短前缀是否保留有效信息？ | 单学生比较 multi-width、full-only 后截断及独立宽度接口；分开控制 slot 和宽度 | 短前缀有效、满宽无不可接受退化、重复种子方向一致 |
| 5. 跨学生共享 | 同一信息排序是否适配不同能力学生？ | private/shared × full-only/multi-width 四格；逐学生非劣界限和共同成本口径 | 所测学生均无稳定负迁移，然后再做未见宽度和新学生读取器接入 |
| 6. 适用范围与成本 | 收益属于哪类信息需求？ | 数学跨数据集、事实/混合知识问答、证据压缩，之后单独选择工具调用基准；测实际通信和端到端成本 | 每类分别支持结论；质量通过后才检验部署 Pareto 优势 |

文本提示包含答案时只能说明学生能消费答案，不能证明推理迁移。训练时原生状态对齐属于待验证辅助监督，不等于部署时可以偷偷使用学生问题 Prefill。工具执行后的新信息不能由一次初始教师 Prefill 自动更新，需要另行规定动态协议。

下一版应先从前三项选一个明确瓶颈和有限对照注册，避免将容量、数据、损失和接入方式同时改变。无收益和不确定结果也属于研究产出；不应无限扩大搜索直到出现一个正分数。
